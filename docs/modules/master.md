# Master: CplugMaster (unit plugCore) and the CSynth glue

C++: `src/engine/Master.{h,cpp}`, `src/engine/Voice.h`, `src/engine/VoiceModules.h`,
data `src/engine/data/MasterData.cpp` (generated by `re/scripts/extract_master_data.py`).
Test: `tests/capi_master.cpp`, `tests/test_master.py`, `tests/test_master_capture.py`.

The master owns the 16 voice records (128 in the port, see *More polyphony* below), voice
allocation and stealing, poly/mono/legato note handling, the control-rate modulation engine
(mod sources, matrices, parameter updates of LFOs, envelopes, oscillators, filter, amp),
per-sample voice rendering, the "muffle" shelving filter and the output stage. Original
class CplugMaster, instance size 73812 (0x12054), code 0x461c7c–0x4648a4.

## Modulation sources (FUN_00463808, table 0x4c4848)

The 16-bit source numbers in the program are looked up in a table built by the
midiParser unit initialization (FUN_0044feec; computed in C++):

| source | value |
|---|---|
| -1 | 0 (none) |
| 0..3 | `voice.mod[0..3]`: LFO 1-4 outputs (lfoTick) |
| 4..7 | env 1-4 outputs (envTick) |
| 8, 9 | velocity curves 0x494d4c / 0x494dcc (`kVelocityCurve1/2`) |
| 10 | key (0..127) |
| 11 | key scaling: key ≤ 32 → -128, ≥ 95 → 124, else (key-64)*4 |
| 12 | poly pressure of the voice's key (refreshed every full update) |
| 13..15 | MAT1..MAT3 |
| 16+n | MIDI controller n (CC 0..127, 0x80 channel pressure, 0x81 pitch bend/64) |
| 0x81 | 0 (special case: would be CC 113) |
| 0x91 | pitch bend/64, only while `voice.bendActive` |
| < -1, > 0x91 | 0 |

Matrices (program 0xe2 + 12*i, i = 0..2: sources at +0/+3/+6/+9, amounts at +2/+5/+8/+0xb):
`mat = (s1*a1 + s2*a2 + s3*a3) * ((s4 - 127) * a4 + 8001) / 504063` with 32-bit wrapping
products; 0 when both factors are 0. MAT2 sees the new MAT1, MAT1 the old MAT2/3.

## Routines

* **process** FUN_004645c8: under RZ. Silence (if replacing) when `error`, `lockCount > 0`
  or `numVoices <= 0`; otherwise parser beginBlock, per sample: parser tick; if voices
  sound: acc = 0, processVoice for each list entry (count read once), kill the finished
  ones afterwards, muffle if on, out = float(acc*volume) (+ out when accumulating); else
  0 (replacing). The parser endBlock runs in every case (also in the silent paths, so
  notes still start).
* **processVoice** FUN_00464410: age--, control countdown; on reload: control update if
  env 4 is active, then docStopVoice if env 4 is (now) inactive. Finished (returns true)
  when env 4 is inactive and `ampRampCount <= -docReleaseSamples`. Else docRender →
  filter[0].process → ampProcess, or ampProcessFaded with the fade gain (step per
  sample; at the end the voice is finished if `fadeKill`).
* **controlUpdate** FUN_00463890: odd ticks only docInterpolateLevels. Full ticks: poly
  pressure, glide (follTick), pitch bend by mode program[0x191] (1 not released,
  2 newest key `noteStacks[0]`, 3 both, else always; 4..6 = 1..3 without storing the
  bend), envTick ×4, LFO inputs + lfoTick ×4, MAT1-3, Cdoc params + docUpdate, filter
  key param + setParams(FREQ*2 + mods/64, RES, immediate on the first tick), amp
  saturation, level: `e = (Round(prog[0x132]*0.0163810*noteLevel) + CC11/2) * envShaped*2 / 64`,
  `level = Round((CC7 + mod/64) / 127 * e)`; pan `prog[0x133] + panOffset + (mod + CC8 - 64)/128`;
  muffle mode of the newest voice; amp ramp time on the second tick.
* **note on** LAB_00463388 → FUN_00463420: builds the note record (level 0x3f; steal = mode
  != -1, mode = override - 2 or (int8)program[0x195]); noteId = program number << 16.
  Poly: release voices with the same key and noteId; retrigger the first of them when
  program[0x174] (VC) else allocate; push last-key stack. Mono: the voice with the same
  noteId is restarted (stealStart) if released or not mono, else legato
  (startVoice with newNote=0, no LFO/env init). Glide source: last key (poly) or newest
  held key (mono). Note off (velocity 0): release matching voices (key, noteId low word);
  mono voices with another held key glide/retune back to it (retarget).
* **allocate** FUN_0046300c: first free (or age 0) playable voice, else the oldest released,
  else the oldest. **stealStart** FUN_00462c04: with steal on, the slot moves to a fade
  slot (oldest/free one from FUN_004630cc) and fades out over 5 ms while the new note
  starts in the freed slot (slots are swapped in slotMap). **startVoice** FUN_004625d4:
  see source; when the note takes over a voice with the same key and noteId and VC is on
  (program[0x174]) it fades in (FUN_00462f18), copies filter/amp state and continues the
  envelopes unless ENV restart (program[0x175]).
* **midiControl** FUN_00463714: CC123 kills every active voice immediately; pitch bend is
  stored raw and as /64; poly pressure per key; then the controller table. (port, issue #40)
  CC0 is also latched as the bank for the next program change, in `bankSelect_` rather than
  read back out of `ctrl_`, whose 0 is both "bank A" and "nothing has arrived yet". It still
  goes into the controller table, so CC0 keeps working as a modulation source.
* **midiProgramChange** (port, issue #40): no original. The parser only makes a record for
  0xC0 when `setProgramChangeEnabled(true)` has been called — off, 0xC0 is dropped at parse
  time exactly as the original drops it, so the record stream stays identical and the
  differential test compares unchanged. On, the record dispatches at its own sample like any
  other, and the master hands the program and the latched CC0 to `onProgramChange`; the owner
  (`Synth`) resolves the bank and loads through the edit buffer, whose ring and
  kill/release of the slot being reused are what make a mid-block switch safe. The channel is
  ignored, like note on. See `library.md` for the switch's place in the chunk.
* **setSampleRate** FUN_00462214, **setControlRate** FUN_00462380, **setVoices**
  FUN_00463358/FUN_004632e4, **reset** FUN_00462174/FUN_00462570: see source.
* **muffle**: high shelf (treble cut), A = 10^(-1/8), w = 19521.857/sr (2π·3107 Hz),
  coefficients FUN_00464250 (RBJ form with beta = sqrt(A/0.71)); state reset when switched
  on (FUN_004643c8); stereo biquad FUN_004644f4. The mode follows the newest voice: override +0xfe8 - 1, else
  program[0x13b] bit 2.

## ini overrides (FUN_004620e4)

`loadOverrides(ini)` takes the 5 [synth] values in config-index order (FUN_00452c5c(cfg, i)):
0 → +0xfe4 voice stealing, 1 → +0xfec DCA1-3 smoothing, 2 → +0xff0 DCA4 smoothing,
3 → +0xfe8 muffle, 4 → +0xff4 DC blocking. 0 = set by the program, else option + 1.
Quirk: the SQ8L.ini key names read into these indices are voiceStealMode, muffleMode,
oscDcaMode, dca4Mode, dcbMode, i.e. "muffleMode" drives DCA1-3 smoothing, "oscDcaMode"
DCA4 smoothing and "dca4Mode" the muffle.

## Floating point

`process` runs in RZ (x87 CW|0xC00); setup code (constructor, setSampleRate,
setControlRate) in the caller's mode (host: nearest). Notes dispatched from
`processEvents` (leftover flush) run in the caller's mode, those dispatched in `process`
in RZ: `Round()` (fistp) truncates there, e.g. for the fade lengths. 80-bit constants are
split hi/lo (`mulExt`); one division by an 80-bit constant (0.71) uses `divExt`.
`Power` = exp(e·ln b); `Cos`, `Sqrt` from libm (rounded to float).

## Quirks (faithful)

* Note off compares only the low word of noteId (always 0), so it releases notes of any
  program; poly retrigger and mono matching compare the full noteId (program number).
* The steal-start sets `stolenFrom` to the slot's current voice even when no stealing
  happens (it may be the voice itself: legato with VC compares the old key/noteId).
* `stealFlag`/fades: a stolen voice fades out in a fade slot over Round(sr*0.005) samples.
* CC123 kills voices immediately (no release); pitch bend source 0x91 only applies to
  voices whose bend is active (mode); source 0x81 always reads 0.
* Bend modes 4..6 compute the bend but keep the previous one stored in the voice.
* The matrix and LFO products wrap at 32 bits (IMUL).
* processVoice's tick parity can never be negative: the `parity < 1 → +1` branch is dead.
* Negative program[0x9b] (bit 7 set) gives a negative fade-in index; the original reads
  code pointers before the table (tiny floats): length 0. C++ uses 0 (exact for -1..-24).
* Fields computed but never used: `sampleRateMs_`, `smoothA_/B_`, `tickToggle_`, `fe4`.
* `controlRate` is clamped to [1, sr]; the first setSampleRate in the constructor runs with
  rate 0 → 1.0 before the real rate is set.
* Module objects are reached through `voice` index, Cdoc through `voice.slot` (equal).

## Testing

`tests/test_master.py` (with `test_master_capture.py`): the emulated original plays
scenarios (poly chords on 12 programs, 14-note stealing with/without fades, fade-slot
exhaustion, VC retrigger with/without env restart, mono legato with and without glide,
held-key stack overflow, poly glide, the 8 bend modes with several ranges, CC1/7/8/11/74,
channel and poly pressure, sustain, CC123, MIDI reset/stop, panic, program changes while
notes sound, edit-buffer events 0..5, muffle programs, every ini override value, Cdoc
program bits, randomized modulation routings (24 patterns incl. out-of-range, 0x81 and
bend sources), long tails, sample rates 48k/96k/32k(error)/44.1k, control rates
0.5/100/1e7, voice counts 6+4/3+2/1+1/12+4/0+0, active voice counts, accumulating, nil
output and locked process calls). Captured units: note callbacks, controller callbacks,
resets, control updates (sampled), voice processing (sampled), setSampleRate,
setControlRate, setVoices, edit events, active counts, override loads, whole
processEvents+process blocks, and the constructor. Each is replayed on the C++ master:
same module call sequence and arguments (and LFO/Cdoc parameter blocks at the call),
identical master/voice/filter state, identical outputs. `--quick` runs a shorter set.
Branch probes on 144 basic blocks of the original report which paths were verified;
the 4 never reached are dead code (negative tick parity, sr < 100 fade length, nil note
record, nil voice in modSource).

The test also documents an emulator pitfall: Unicorn does not re-check code hooks for
blocks translated before the hook was added, so hooks installed after the plugin ran
(`Win32Emu.trace`) can silently miss calls; `test_master_capture.CodeHook` flushes the
translation cache.

## More polyphony (port addition)

The original allocates 16 voice slots and uses them as 8 playable voices plus 8 fade slots
(`setVoices(8, 8)`): with soft stealing, a voice taken over moves to a fade slot and fades
out there while the new note starts. The port sizes every per-voice array (master, Cdoc,
LFOs, envelopes, amp, followers, filters) for `kMaxVoiceSlots` = 128 (`VoiceSlots.h`) and
has two layouts:

* the original's, set by the constructor (`setVoices(8, 8)`): playable slots 0..7, fade
  slots 8..15. The differential tests use it, so they still drive the original's modules for
  slots 0..15 only;
* the port's, `setPortLayout()`, which the plugin always uses (`Synth`): 64 playable slots
  (0..63) and 64 fade slots at `kFadeSlotBase` (64..127), so the voices of any polyphony can
  fade out. The fade slots *in use* are as many as the playable voices, like the original's
  8 + 8 (`findStealTarget`): with all of them busy the original re-steals the oldest instead
  of finding a free one, and the heavy-stealing regression cases hear the difference.

Both are expressed in `slotMap_`, through which everything reaches the voices, plus
`fadeBase_` (the first fade entry: `numPlay_` for the original, `kFadeSlotBase` for the
port). The playable voices are then only a **limit on the allocator**,
`effectivePlayableVoices()`: the per-instance override (OPTIONS -> Polyphony,
`setPolyphonyOverride`, 0 = set by the program) or else the current program's `VOICES`
(`ofs::Polyphony`, 0 = the original's 8), clamped to 1..64 and read at every note on. So a
program change, a parameter edit or a menu choice never resets the engine and never stops a
note: voices above a lowered limit simply keep playing until they end. The scans that look
for a voice to release or retarget run over the whole playable region (`fadeBase_`), so
those voices still respond to note off.

With 8 voices and no override this is bit-exact: the slots carry identical per-voice state
and `process` accumulates over `list_` in note-start order, not in slot order, so moving the
fade slots does not change a single sum (243/243 regression renders). With more voices, a
performance renders identically as long as it never takes over a sounding voice with 8
(`Master::stealCount`, `render_check --polyphony`). The output is not rescaled: more voices
sounding together add up to a higher level.

## Filter types (port addition)

FILT -> TYPE (`ofs::Filter::Type`, program byte 0x110, `programFilterType`, see
[program.md](program.md#filter-type-port-addition-0x110)) picks the filter a voice plays:
0, what every program the original made has, is `filters_[v][0]` (`FilterSQ`) exactly as
before; 1..5 are `svfs_[v]` (`FilterSvf`, `src/engine/FilterSvf.{h,cpp}`), a linear
trapezoidal state variable filter after Andy Simper (Cytomic, *SvfLinearTrapOptimised2*):
LP2, BP2, HP2, NOTCH (2-pole) and LP4 (two cascaded 2-pole stages with the Butterworth Qs
0.54 and 1.31, the resonance on the second); 6 is `cems_[v]` (`FilterCem`,
`src/engine/FilterCem.{h,cpp}`), CEM, a nonlinear model of the SQ-80's CEM3379 (below);
7..11 are `vas_[v]` (`FilterVa`, `src/engine/FilterVa.{h,cpp}`), MOOG, MS-20, SSM, WASP and
303, nonlinear models translated from Filther (below).

The SVF takes FilterSQ's inputs: the same cutoff index (`FREQ * 2` plus key tracking, the
two FREQ modulation slots and CC74, computed once in `controlUpdate`) looked up in the same
`filterUnitTables().cutoffHz`, and RES 0..31. `SvfTable` (rebuilt with `FilterTable` on a
sample rate change) holds `g = tan(pi fc / sr)` per index, with fc clamped to 0.49 sr like
FilterSQ's; RES sets Q from the stage's Butterworth value up to 16 exponentially, so k = 1/Q
is never 0 and the filter cannot run away at any sample rate. The cutoff is smoothed per
sample *as an index* (log frequency) and g interpolated between table entries, k and the
output gain likewise, with FilterSQ's smoothing time, so control-rate modulation steps sweep
instead of clicking. LP2, HP2 and LP4 take the original's resonance gain compensation
(`resoGain`); BP2 (normalised to 0 dB at the cutoff) and NOTCH never rise above unity. State
is double precision, far from the denormal range whatever the input.

### CEM (FilterCem)

A model of the Curtis CEM3379's 4-pole lowpass, written for the port from published
descriptions: Huovilainen's nonlinear ladder (DAFx-04) for the structure, Zavalishin's *The
Art of VA Filter Design* for the discretisation, the CEM3379/CEM3320 datasheets for the
input feed-forward, and MAME's `esq1_filters` (`src/mame/ensoniq/esq1.cpp`, BSD-3-Clause)
for the linear limit and the resonance law; Joep Vanlier's Filther (MIT) served as a
cross-check. No code was taken from any of them.

Four OTA stages, each a trapezoidal integrator driven by the tanh of its input minus its own
output, `y_i = s_i + g tanh(y_(i-1) - y_i)`, then `s_i = 2 y_i - s_i`; the first stage's input
is the resonance node `u = (1 + a r) x - r y_4`. That loop has no unit delay in it
(zero-delay feedback): it is solved per sample by Newton's method, starting from the
stages' last currents, until a correction is below 1e-5 (at most 4 iterations, about 1.2-2.2
on average). The Jacobian is lower bidiagonal plus the feedback term in its corner, so each
correction is one forward pass and one division, by a number never below 1. tanh is
Lambert's continued fraction to x^7/x^6, clamped at +-4.97 (within 2e-7). A small signal
sees exactly MAME's `(1 + a r) / ((1 + s/wc)^4 + r)` with the feed-forward share a = 0.375
(MAME has a = 1, a passband that never drops), so the passband falls by half (6 dB) at the
oscillation threshold r = 4 instead of to a fifth.

`CemTable` holds `g = tan(pi fc / (2 sr))` per index: the model runs at twice the sample
rate, the input upsampled and the output decimated by a 31-tap Kaiser halfband (beta 7;
-0.3 dB at 0.41 sr, -67 dB from 0.64 sr, 15.5 samples of delay). Cutoff and resonance come in
as for the SVF (`cutoffHz`, clamped to 0.49 sr, the index smoothed per sample, g
interpolated).

Calibration, all of it a guess until measured against a real SQ-80:

* RES: the SQ-80 shifts RES left by 2 into its 5 V DAC, so RES 31 is CV_Q = 2.43 V (Rainer
  Buchty in sq8l-revival/SQ8L issue #41). r is linear in CV_Q, as in MAME, and reaches 4 at
  the datasheet's minimum oscillation voltage, 2.2 V (2.8 V typical): this is a hot part,
  self-oscillating at RES 29-31 and settling at a bounded level (about 0.4-0.7). A typical
  part would not oscillate at all.
* Drive: the input is scaled by 1.35 before the stages and the output divided by it, so
  one oscillator at full level (amplitude 1) an octave below the cutoff comes out with about
  1% THD, all three at full level about 3.5%.
* No `resoGain`: the feed-forward already sets the passband level.

It costs about 100-170 ns per voice-sample on a desktop x86-64 (the SVF a few ns), most of
it the tanh and divisions of the Newton iterations.

### MOOG, MS-20, SSM, WASP, 303 (FilterVa)

Five models translated from Joep Vanlier's Filther (MIT), the 303 being Dominique Wurtz's
diode ladder (MIT); see the comments in `FilterVa.h` / `FilterVa.cpp` for which Filther
function each one is and THIRD_PARTY_NOTICES.md for the licences. Each is a set of node
equations with trapezoidal integrators and the nonlinearities inside the loop, solved per
step with Filther's 3 Newton iterations from the last state (the 303: the linear ladder
solved exactly, its input hard-clipped):

| Type | Model | Order | Resonance (RES 0..31 = Filther's 0..1) |
|---|---|---|---|
| MOOG | transistor ladder, tanh stages | 4-pole LP | k = 4.4 q, self-oscillates near the top |
| MS-20 | Sallen-Key, atan integrators, diode-clipped feedback | 2-pole LP | k = 2 q, the clip bounds oscillation |
| SSM | SSM2040 OTA cascade, tanh stages and feedback | 4-pole LP | K2 = 5 q |
| WASP | CMOS-inverter state variable filter | 2-pole LP | damping r = 0.8 - 0.6 q (Q about 2 to 8) |
| 303 | TB-303 diode ladder | 4-pole LP | k = 20 q, output scaled by 1 + k/2 |

They share the CEM model's machinery: `cemTable_` for `g = tan(pi fc / 2 sr)` per index (each
model's integrator gain is set from it so that its linear natural frequency is the cutoff,
where Filther scales its own frequency axis per model; the WASP and 303 are then tuned by
`retune`, which scales the prewarped angle, so their RES 28 peak lands on the cutoff), the
same 2x halfband resampling (`FilterCem::halfbandTaps`), cutoff index and resonance smoothed
per sample, and the filter FM offset delayed with the input. A non-finite step clears the
model's state. Measured (render_check --filter-types): passband 0.98-1.01, RES 28 peak at
0.97-1.00 of the cutoff, bounded on full-scale noise at RES 31 under jumping cutoffs. Cost
per voice-sample on a desktop x86-64: 303 about 120 ns, MS-20 190, WASP 200, SSM 290, MOOG
320 (CEM 150). The WASP keeps Filther's 0.01 bias in its inverters, so it rests at an output
offset of about -0.005.

### Switching

`filterType_[v]` is the type the voice plays. It is set at a note start (a legato steal
inherits the stolen voice's type and SVF, CEM and FilterVa state, as FilterSQ copies its
state) and followed at every control tick: switching to another filter object (FilterSQ, the
SVF, the CEM model, or another FilterVa model, whose states mean different things) while a
note plays clears the one taking over and puts it on its target
immediately; switching between SVF types keeps the state. FilterSQ still gets its
`setParams` every tick whatever the type, and its `process` only runs for type 0, so a type
0 voice is untouched (243/243 regression renders). `render_check --filter-types` checks the
response of each SVF type at 44.1-384 kHz, resonance, fast modulation and smoothing; for CEM
the small-signal response against the formula above, distortion against the level,
self-oscillation (RES 31 rings at every cutoff, RES 27 dies away), fast modulation of a
loud input and smoothing; and whole programs with every type.

## Filter FM (port addition)

FILT -> FM SRC / FM AMT (`ofs::FilterFmSource` / `ofs::FilterFmAmount`, program bytes
0x13d / 0x13e, `programFilterFmSource` / `programFilterFmAmount`, see
[program.md](program.md#filt-fm-src--fm-amt-port-addition-0x13d-0x13e)) move the filter cutoff
at audio rate by one of the voice's oscillators. The original has nothing like it: every
modulation source reaches the filter through `controlUpdate` at the control rate.

`controlUpdate` reads both at every full tick into `fmSource_[v]` (the oscillator 0..2, -1 =
OFF) and `fmDepth_[v]` (AMT * 2 cutoff index steps per unit of the oscillator's output, i.e.
AMT FREQ steps at full swing). `processVoice` then branches once per sample:

* OFF (every program the original made, the constructor's value, and a source byte outside
  1..3): `process` of the type the voice plays, the code above, untouched (243/243
  regression renders).
* On: right after `docRender`, `VoiceModules::docOscSample(v, src)` gives the oscillator's
  sample, which times `fmDepth_` is the offset in index steps for `processFm` of the type the
  voice plays.

The modulator is the oscillator **before its DCA** (`Doc::oscSample`: the last two DOC samples
of that oscillator, `wave byte - 128` scaled like the sum, interpolated at the resampler phase
`render` used; kept in `Doc::tap`, outside the original's image like `clock` and `direction`).
Before rather than after, so that an oscillator switched ON at LEVEL 0 is a filter modulator
nobody hears, and the depth is FM AMT alone, not also the oscillator's level, DCA modulation
or AM. An oscillator whose OUTPUT is off is halted by the DOC and reads 0, except OSC1
while it is the SYNC or AM source of an enabled OSC2, which the DOC keeps running silently.

`FilterSvf::processFm` adds the offset to the smoothed index, clamps it to 0..255 and
interpolates g as before: the table's top is below Nyquist at any sample rate, and g follows
the cutoff every sample. `FilterCem::processFm` does the same at twice the rate, for both of
its steps: its upsampler delays the input by 8 samples, so the offset is delayed by as many
(the step halfway takes the average of its neighbours) to stay in phase with the audio it
moves, which matters when the modulator is the carrier's own oscillator; the Newton solve
copes with g changing every step. `FilterSQ::processFm` keeps the original's smoothed p, k
and g and adds to them the difference the table makes between the target cutoff and the
moved one (interpolated, pole clamped to the column's range, feedback likewise; the column
runs monotonically, which the check verifies). It runs the four stages as TPT one-poles
(`FilterSQ::tpt`): each of the original's stages, `y = g (x + x') - p y'` with
`g = (1 + p) / 2`, is the bilinear one-pole, and so is a TPT one-pole of the same g, so with
the settings held still it is the original filter (the resonance loop keeps its one-sample
delay, `stage[4]`, around which the tables are tuned). Only under modulation do they differ:
the TPT integrators keep their state through coefficient changes, so fast, deep FM pumps far
less energy into the ladder. On the first sample with an offset the integrator states are
derived from `stage[]` (`s = (g x' - p y') / (1 - g)`), and every sample still writes
`stage[]`, so `process` and `processFm` hand over to each other without a seam; until that
first offset `processFm` is `process`. Being linear, the ladder can still run away near
self-oscillation, so the FM path soft-limits every stage above 32 (the unmodulated stages
reach about 10 to 15 on full-scale noise through unsmoothed jumps of cutoff and resonance,
rarely more), which bounds the output near 33; `process`, which every voice without filter FM
runs, has no limit and is the original's arithmetic. With no FM every `processFm` is its
`process` bit for bit. `render_check --filter-fm` checks all this (for the SQ-80 type also
that a constant offset is the original at the moved cutoff and that the handover leaves no
seam, both to rounding), plus sidebands around a carrier,
full-swing FM at 44.1-384 kHz on every type, and whole programs (OFF / amount 0 / unknown
source / disabled oscillator render like OFF; extremes stay finite; every voice of a chord
follows).
